# 2048 — 逻辑配置文档

## 1. 页面流转

| 状态 | 触发条件 | 目标状态 | 说明 |
|------|----------|----------|------|
| 游戏中 | 进入游戏（自动初始化） | 游戏中 | 随机生成 2 个数字方块（90% 为 2，10% 为 4），计分归零 |
| 游戏中 | 任意方向滑动且有方块移动 | 游戏中 | 方块滑动合并，生成新方块，分数更新 |
| 游戏中 | 某个方块达到 2048 | 游戏中 | 标记为已获胜，播放胜利音效，但游戏不结束，可继续挑战更高分 |
| 游戏中 | 棋盘满且无法再合并 | 结算 | 弹出结算对话框，显示最终分数 |
| 结算 | 点击"再来一局" | 游戏中 | 重置棋盘和分数，重新生成初始方块 |
| 结算 | 点击"返回" | 退出游戏 | 回到主菜单 |
| 游戏中 | 点击暂停按钮 | 暂停 | 画面变暗显示暂停遮罩 |
| 暂停 | 点击继续按钮 | 游戏中 | 恢复游戏 |

## 2. 布局结构

- **棋盘区域**：4 × 4 的方格棋盘，居中显示，正方形，取屏幕宽高较小值作为边长。
- **方格间隔**：方格之间有 6dp 的间隙，间隙颜色与背景一致（深色）。
- **空格样式**：深蓝灰色圆角方块。
- **数字方块**：圆角方块，颜色随数值变化——2 和 4 为浅色（白/灰），8 起逐渐变为橙色、红色，128 起为金色系，2048 为亮红色。数字 2 和 4 使用深色文字，8 及以上使用白色文字。字号随数字位数自动缩小。
- **已获胜提示**：当棋盘上存在 2048 方块且游戏未结束时，棋盘上方显示金色提示文字"已合成 2048，继续刷高分！"。
- **无动画**：方块移动、合并、生成均为瞬时切换，无过渡动画。

## 3. 按钮及交互功能

| 控件 | 位置 | 交互方式 | 功能 |
|------|------|----------|------|
| 屏幕滑动 | 游戏画面任意位置 | 快速滑动（Fling） | 向四个方向之一滑动，所有方块朝该方向移动并尝试合并 |
| 暂停按钮 | Activity 悬浮层 | 点击 | 暂停/继续游戏 |
| 重开按钮 | Activity 悬浮层 | 点击 | 重置游戏 |

滑动需达到最低速度阈值（80 像素/秒），否则不触发移动。

## 4. 核心规则

- **棋盘**：4 × 4 方格。
- **初始状态**：随机在两个空格中各生成一个数字（90% 概率为 2，10% 概率为 4）。
- **滑动规则**：玩家向四个方向之一滑动，所有数字方块沿该方向移动，直到碰到边界或其他方块。
- **合并规则**：同一行/列中，相邻且数值相同的方块在滑动时会合并为一个方块，数值翻倍。每一步中，每个方块只参与一次合并（不会连锁合并）。合并时，合并后的数值同时加到本局得分中。
- **新方块生成**：每次有效滑动后（至少有一个方块移动或合并），在随机空格中生成一个新数字（90% 为 2，10% 为 4）。
- **得分**：每次合并产生的新数值累加到总分中。例如两个 64 合并为 128，得分增加 128。
- **游戏结束**：棋盘已满且没有任何相邻方块可以合并时，游戏结束。
- **胜利判定**：棋盘上出现数值为 2048 的方块时，标记为已获胜。但游戏不会自动结束，玩家可以选择继续游玩冲击更高分数。

## 5. 特殊规则

- **无操作保护**：如果滑动后没有任何方块移动或合并，则不生成新方块，得分不变，相当于该次操作无效。
- **合并优先级**：滑动时，靠近移动方向的方块优先合并。例如向左滑动时，每行最左侧的相同数字优先配对。
- **已获胜后继续**：达到 2048 后游戏不锁定，玩家可继续合并。若之后无法移动，结算时仍以已获胜状态结算。
- **颜色映射**：超过 2048 的方块（如 4096、8192 等）使用 2048 的颜色，文字正常显示。
- **字号自适应**：一位数和两位数使用较大字号，三位数及以上使用较小字号，确保数字在方格内完整显示。

## 6. 双人视角

本游戏为单人模式，无双人视角设计。
