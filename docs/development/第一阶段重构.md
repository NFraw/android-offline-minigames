# 第一阶段重构：混合游戏承载层

本阶段把正式 `plane` 入口迁移到 Godot，保留其原生源码，其余 27 款游戏继续使用 Canvas。游戏总数仍为 28。

## 分工

- `GameSpec.runtime` / `GameRuntime`：声明 Canvas 类或本地 Godot 场景，不把所有游戏强制转换成 GameView。
- `GameLauncher`：大厅卡片和历史弹窗统一选宿主。
- `GameActivity`：原生 Canvas 宿主，继续提供旧游戏的交互流程。
- `EngineGameActivity`：Godot 宿主，仅加载注册表声明的本地场景；运行在 `:godot` 独立进程。
- `GameContent`：游戏内容契约，提供规则文案、生命周期和得分/生命/结束信号。
- `GameShell` / `GameSession`：通用开局、暂停、恢复、设置、重开和一次性结算。
- `GamePlatform` / `MiniGamesHost` / `GamePlatformProvider`：Godot → JNI 插件 → Binder → 主进程服务。
- `ScoreStore.saveOnce`：成绩、历史、回执同时 commit，每款游戏保留最近 128 个回执。

主进程负责设置和成绩。引擎子进程只通过平台协议读取或更新它们，避免两个进程的 SharedPreferences 缓存不一致。清除最高分仍保留历史和回执。

## 第一款游戏

`godot/games/plane/`：

- `plane_model.gd` 是纯规则模型，负责生成、射击、移动、碰撞、计分和结束，不绘制或访问 Android。
- `plane.gd` 消费模型状态和事件，负责战机精灵、星空、尾焰、命中特效和触摸。
- `assets/*.svg` 是本项目编写的矢量美术，随包导入为纹理，无运行时下载。
- `plane.tscn` 配置游戏标题、说明和按钮文案。

与原版规则一致：0.28 秒自动射击；首架敌机延迟 1.2 秒；击落 +10 分；漏过敌机扣一格防线；初始三格；直接相撞立即结束。没有增加敌方子弹、升级或道具。

输入把战机放在手指上方 55 个逻辑单位，避免遮挡；Y 轴仍限制在下方区域，底部额外留出提示安全区。子弹使用线段扫掠检测，一颗子弹只消灭一架敌机，避免低帧率漏判与一弹多杀。

## 后续游戏接入

1. 在 `godot/games/<id>/` 创建继承 `core/game_content.gd` 的场景，并配置标题、规则、操作提示及可选生命值上限。
2. 实现 `prepare()`、`start_round()`、`set_game_paused()`；通过三个公共信号汇报得分、生命和结束。
3. 在 `GameRegistry` 注册 `runtime = GameRuntime.Godot("res://games/<id>/<scene>.tscn")`，无需提供 View 类。
4. 同步权威状态文档与游戏规则文档。
5. 给纯逻辑模型加回归用例，验证安卓启动、后台暂停、重开、结算及返回大厅。

## 验证命令

```powershell
powershell -ExecutionPolicy Bypass -File scripts/Test-Godot.ps1
powershell -ExecutionPolicy Bypass -File scripts/Build-Android.ps1 -Test -Instrumented -Device emulator-5554
powershell -ExecutionPolicy Bypass -File scripts/Build-Android.ps1 -Release
```

`RuntimeRoutingTest` 覆盖引擎路由和非法场景路径；Godot 用例覆盖对局门闩、复位、碰撞及终止后的冻结。`EngineIntegrationTest` 通过实际平台服务验证设置、正分保存和回执防重，并启动真实引擎进程验证返回大厅；原生游戏继续运行原有测试。

## 本阶段边界

这是第一阶段可玩的重构样板，尚未迁移其他 27 款游戏、改版整个大厅或增加关卡体系。后台保留同一进程内的暂停对局；进程被杀后从开局页进入，尚未实现中途存档。实体手机性能、耗电与触控手感还需真机验证。
